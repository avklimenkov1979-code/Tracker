# Загрузка накладной по фото — внешняя обработка для 1С:ERP 2.5

Фотографируете бумажную накладную (ТОРГ-12, УПД, счёт-фактура, товарная накладная) или берёте скан в PDF,
обработка распознаёт её через Claude API и создаёт документ **«Приобретение товаров и услуг»**.
Документ только записывается, не проводится, поэтому перед проведением его можно проверить.

## Как это работает

1. **1. Выбрать фото накладной** — выбираете один или несколько файлов (JPG, PNG, WEBP, PDF). Несколько файлов
   считаются страницами одной накладной.
2. Распознавание запускается сразу после выбора (повторно — кнопкой **Распознать ещё раз**). Файлы уходят в Claude API (модель `claude-opus-5-5`), обратно приходит JSON строго
   по схеме: номер и дата, поставщик и покупатель с ИНН и КПП, строки с артикулом, количеством, ценой,
   ставкой и суммами НДС, итоги и список замечаний («не читается строка 5», «сумма строк не сходится с итогом»).
3. Обработка сама подбирает:
   - **контрагента** по ИНН (если найдено несколько, сначала берётся тот, у которого совпадает КПП), а по нему **партнёра**;
   - **организацию** по ИНН покупателя;
   - **номенклатуру** в таком порядке: сохранённое ранее сопоставление для этого поставщика → артикул →
     точное наименование → полное наименование → единственное совпадение по началу наименования.
     Если подходящих вариантов несколько, номенклатура не подставляется: её выбирает пользователь.
4. Строки, где номенклатура не подобрана, выделены цветом. Её нужно выбрать вручную. Ваш выбор
   запоминается, и в следующей накладной от этого же поставщика номенклатура подставится сама.
5. **2. Создать поступление** — документ создаётся с хоз. операцией «Закупка у поставщика»,
   с номером и датой входящего документа, а затем открывается.

## Установка

### Вариант А — `СОБРАТЬ.bat` (рекомендуется)

Скрипт находит установленную платформу 8.3, создаёт временную пустую файловую базу и
собирает `Nakladnaya_po_foto.epf` командой ниже. Если сборка не удалась, скрипт показывает лог.

Вручную то же самое делается так: в Конфигураторе любой базы на платформе 8.3.15 или новее:
**Файл → Загрузить внешнюю обработку, отчет из файлов...** → укажите
`src/ЗагрузкаНакладнойПоФото.xml` → **Файл → Сохранить как...** `ЗагрузкаНакладнойПоФото.epf`.

Тот же шаг из командной строки:

```
1cv8.exe DESIGNER /F"C:\Базы\ERP" /N"Администратор" /P"" ^
  /LoadExternalDataProcessorOrReportFromFiles "src\ЗагрузкаНакладнойПоФото.xml" "ЗагрузкаНакладнойПоФото.epf"
```

### Вариант Б — вручную (если загрузка из XML не прошла)

Все реквизиты и элементы формы создаются программно, поэтому собрать обработку можно примерно за 2 минуты:

1. Конфигуратор → **Файл → Новый → Внешняя обработка**, имя `ЗагрузкаНакладнойПоФото`.
2. **Модуль объекта**: вставьте содержимое `src/ЗагрузкаНакладнойПоФото/Ext/ObjectModule.bsl`.
3. Добавьте управляемую форму `Форма` и сделайте её основной. В модуль формы вставьте
   `src/ЗагрузкаНакладнойПоФото/Forms/Форма/Ext/Form/Module.bsl`.
4. В свойствах формы, на закладке «События», назначьте **ПриСозданииНаСервере** → `ПриСозданииНаСервере`.
5. Сохраните как `.epf`.

### Запуск

1С:ERP → **Файл → Открыть** → `ЗагрузкаНакладнойПоФото.epf`. Можно также зарегистрировать файл в
справочнике «Дополнительные отчеты и обработки».
Ключ API программа запросит сама при первом распознавании и сохранит его. Поменять ключ можно на закладке **Настройки**.

## Настройки

| Поле | По умолчанию | Описание |
|---|---|---|
| Адрес API | `https://api.anthropic.com` | Сюда можно указать адрес своего шлюза или прокси, если сервер 1С не ходит в интернет напрямую. Путь после хоста учитывается (`https://gw.example.ru/anthropic` → `.../anthropic/v1/messages`). |
| Ключ API | — | Ключ из console.anthropic.com. Хранится в хранилище общих настроек текущего пользователя. |
| Модель | `claude-opus-5-5` | |
| Тщательность | `high` | Параметр `effort`. `medium` быстрее и дешевле, `xhigh` лучше справляется с мятыми и тёмными фото. |
| Резервная модель при отказе | включено | Если основная модель откажется отвечать, запрос автоматически выполнит резервная модель (параметр `fallbacks: "default"`). Если ваш шлюз такой параметр не пропускает, отключите. |
| Таймаут, сек | 300 | |

На закладке «Настройки» также виден исходный JSON ответа модели — он нужен, если результат распознавания вызывает вопросы.

## Требования и ограничения

- 1С:ERP 2.5 (проверка реквизитов идёт по метаданным, поэтому должны подойти и 2.4, и КА 2.5; на УТ 11 тоже должно работать, там те же объекты).
  Ставка НДС поддерживается в обоих вариантах: справочником `СтавкиНДС` и старым перечислением; есть и 22 %.
- HTTP-запрос отправляет **сервер 1С** (в клиент-серверном варианте — rphost), поэтому доступ к адресу API нужен именно с сервера.
  Используются системные настройки прокси.
- Размер одного фото не больше ~3,7 МБ: у API лимит 5 МБ после кодирования в base64. Обычно хватает снимка
  с телефона, отправленного через мессенджер, или скана в 150–200 dpi. PDF — до 30 МБ.
- HEIC с iPhone не поддерживается: сохраните снимок как JPG (Настройки → Камера → Форматы → «Наиболее совместимый»).
- Пока идёт распознавание (обычно 20–90 с), форма ждёт ответа.
- Стоимость: одна страница накладной на `claude-opus-5-5` обходится примерно в несколько центов.
- Модель читает документ, но может ошибиться в цифре на плохом фото. Поэтому документ не проводится автоматически,
  а расхождения между суммой строк и итогом накладной выводятся в поле «Проверьте».
