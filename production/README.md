# Производственные отчёты

Скрипты читают таблицы из учёта (CSV или Excel) и собирают отчёты в HTML.
Нужен только Python 3.9+, внешние библиотеки не нужны. Поэтому скрипты работают на
компьютере, на сервере и на телефоне (a-Shell, Termux), как и сборщик цен на фенол.

| Отчёт | Скрипт | Статус |
|---|---|---|
| Ежедневный отчёт руководителю: деньги, долги, заказы, выпуск, нехватка сырья | `daily_report.py`; для 1С:ERP — обработка в `1c/` (собирается `СОБРАТЬ.bat`) | готов |
| Учёт производственных партий: сырьё → варка → сушка → выпуск → ОТК | — | следующий |
| Плановая и фактическая себестоимость | — | после партий |

## Быстрый старт

```bash
python production/daily_report.py --demo            # отчёт на демо-данных
python production/daily_report.py --data production/data
python production/daily_report.py --data production/data --date 24.11.2026
```

Результат появится в папке `reports` внутри папки с данными:

- `daily_2026-11-24.html` — отчёт. Открывается в любом браузере, на телефоне тоже;
  в PDF сохраняется через «Печать» браузера;
- `daily_last.txt` — одна строка для уведомления на телефоне, например:
  `Отчёт 24.11; деньги 22,4 млн ₽; ДЗ 61,8 млн ₽ (просрочено 17,7 млн ₽); выпуск 22,6 т (81 %); заказы 200 т, просрочено 3; нехватка: Фенол, Уротропин`.

По умолчанию отчёт строится на последнюю дату, которая есть в выпуске или платежах.

## Что в отчёте

1. **Главное.** Плитки (деньги, кто должен нам, кому должны мы, портфель заказов,
   выпуск за сутки и с начала месяца, сырьё) и список вопросов, которые требуют решения.
   Сначала критичные, потом требующие внимания, потом крупные платежи дня.
2. **Деньги.** Остатки по счетам и кассе на конец дня и изменение за день; все платежи дня;
   прогноз остатка на 7 дней по срокам оплат с графиком. Прогноз осторожный: просроченную
   кредиторку считаем к оплате завтра, просроченную дебиторку не ждём. Внутренние
   перемещения (снятие в кассу, между счетами) в приход и расход не попадают.
   Есть расходы с начала месяца по статьям.
3. **Долги.** Дебиторка и кредиторка: сколько всего, сколько просрочено, разбивка по
   срокам (не наступил, 1–30, 31–60, 61–90, больше 90 дней). Должники отсортированы
   по просрочке, с комментариями, например «Претензия направлена». Показаны ожидаемые
   поступления и платежи на неделю.
4. **Заказы и отгрузки.** Новые заказы и отгрузки за день и с начала месяца; портфель
   по продуктам: сколько осталось отгрузить, сколько есть на складе, сколько выпустить и
   за сколько суток. Просроченные отгрузки. Заказы на ближайшую неделю с прогнозом
   «есть на складе / успеваем выпустить / не успеваем»: склад распределяется по
   заказам в порядке сроков, остальное берётся из выпуска по среднему за неделю.
5. **Выпуск.** План и факт за сутки по продуктам и сменам, брак, график за 14 суток.
   Месяц: план на сегодня, факт, прогноз на конец месяца, сколько нужно выпускать в
   сутки, чтобы выполнить план. Расход сырья за сутки по нормам.
6. **Сырьё и нехватка.** По каждому материалу: остаток, суточный расход, на сколько
   дней хватит (с поставкой в пути и без неё), срок поставки, статус, сколько и на какую
   сумму заказать. Отдельно: хватит ли сырья на весь портфель заказов. Есть блок о цене
   фенола на бирже, если рядом лежит таблица `phenol_index.csv` от `spimex_phenol`.

### Когда материал отмечается как нехватка

- **нехватка**: остаток кончится раньше, чем придёт поставка в пути (будет простой),
  или поставки в пути нет, а запаса меньше, чем срок поставки;
- **заказать**: запаса вместе с поставкой меньше, чем срок поставки плюс 3 дня, или
  остаток ниже минимального;
- суточный расход считается по нормам. Темп выпуска берётся такой, какой нужен для
  выполнения плана месяца, но не ниже фактического за последнюю неделю.

## Таблицы с данными

Положите файлы в одну папку, например `production/data`. Каждый файл может быть `.csv`
(разделитель `;` или `,`, кодировка UTF-8 или Windows-1251, как сохраняет Excel или 1С)
или `.xlsx` (берётся первый лист). Первая строка содержит заголовки. Регистр и знаки
препинания в заголовках не важны, лишние колонки не мешают. Числа можно писать как
`1 234,56`, даты как `24.11.2026` или `2026-11-24`.

Обязательных файлов нет. Если какой-то таблицы нет, соответствующий раздел отчёта
будет пустым с подсказкой. Примеры всех таблиц лежат в `sample_data/`.

| Файл | Колонки (жирным — обязательные) | Откуда взять |
|---|---|---|
| `balances` | **Дата, Счёт, Остаток** | остатки на конец дня по банку и кассе |
| `payments` | **Дата**, Счёт, Контрагент, Статья, Приход, Расход, Назначение | выписка банка и кассовая книга |
| `debts` | **Вид** (Дебиторка / Кредиторка), **Контрагент**, Документ, Дата документа, **Срок оплаты**, **Сумма**, Оплачено, Комментарий | оборотно-сальдовая по 62 и 60 в разрезе документов |
| `orders` | **Номер, Дата, Клиент, Продукт, Количество, т**, Цена, руб./т, Срок отгрузки, Отгружено, т, Статус | заказы покупателей |
| `shipments` | **Дата, Номер заказа, Количество, т** | реализации; если файл есть, «Отгружено» считается по нему |
| `output` | **Дата**, Смена, **Продукт**, Партия, План, т, **Факт, т**, Брак, т | сменные рапорты |
| `plan` | **Месяц** (`11.2026`), **Продукт**, **План, т** | план производства |
| `stock` | **Материал**, Ед., **Остаток**, Мин. запас, В пути, Дата поставки, Цена, руб./ед., Срок поставки, дней, Поставщик | остатки на складе сырья |
| `norms` | **Продукт, Материал, Норма на 1 т**, Ед. | рецептуры и нормы расхода |
| `finished` | **Продукт, Остаток, т** | склад готовой продукции |
| `settings` | Параметр; Значение | см. ниже |

Если остаток на дату отчёта не внесён, он считается от последнего известного остатка
плюс платежи после него. Названия продуктов и материалов должны совпадать во всех
таблицах; регистр и лишние пробелы не важны.

### Настройки (`settings.csv`)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| Предприятие | — | название в шапке отчёта |
| Горизонт прогноза, дней | 7 | на сколько дней вперёд смотреть деньги, заказы и закупки |
| Рабочих дней в неделю | 7 | 7 — непрерывное производство, 5 — с выходными |
| Допустимый брак, % | 1,5 | выше — предупреждение |
| Крупный платёж от, руб. | 3 000 000 | такие платежи дня попадают в «Главное» |
| Неснижаемый остаток, руб. | 0 | ниже — предупреждение в прогнозе денег |

## Автоматический запуск

Компьютер или сервер, каждый день в 8:10, после выгрузки из 1С:

```cron
10 8 * * * cd /path/to/Tracker && python3 production/daily_report.py --data /path/to/data
```

На iPhone через a-Shell и «Команды» запуск такой же, как у `phenol_index.py`
(см. `spimex_phenol/README.md`). В уведомление выводите файл `daily_last.txt`.
